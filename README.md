# tthq

Encode gameplay clips locally at the highest bitrate TikTok will accept, then upload
them with an exported cookie file — from a local web UI or the command line.

## Why uploads look bad, and what this actually fixes

TikTok always re-encodes what you send it. You cannot turn that off. What you *can*
control is how much quality is left after that pass:

- **Avoid a second lossy generation.** Editing in the TikTok app re-encodes an
  already-compressed file. Encode once, locally, and upload the result untouched.
- **Feed the transcoder a format it handles well:** exactly 9:16, `yuv420p`,
  H.264 High profile, frequent keyframes, high and evenly distributed bitrate.
- **Don't waste the bitrate budget.** At 60fps the same budget is split over twice
  as many frames; grain and camera shake burn bits that detail needs.
- **Use the web upload path.** The desktop uploader skips the mobile app's own
  pre-upload compression pass. This tool drives that path, and TikTok Studio's
  "High-quality uploads" switch is forced on there (it renders checked and
  disabled) — the uploader reads it back and reports its state after each run.

What this cannot do: recover detail your capture never had, or stop TikTok from
serving a low-bitrate rendition on a weak connection or with Data Saver on. Check a
post 10–20 minutes after publishing, on Wi-Fi, before judging the result.

## Install

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e .
playwright install chromium   # only needed for uploading
```

FFmpeg (with `ffprobe`) must be on `PATH`: `apt install ffmpeg` or `brew install ffmpeg`.

## Cookies

Uploading reuses your logged-in TikTok session instead of a developer app:

1. Sign in to <https://www.tiktok.com> in your browser.
2. Export the cookies with any cookie-export extension. Both formats work and the
   format is detected from the file contents, not its name:
   - Netscape `cookies.txt` (what yt-dlp uses)
   - JSON array from Cookie-Editor / EditThisCookie (a `{"cookies": [...]}` wrapper
     is fine too)

   Make sure the export includes `httpOnly` cookies, or `sessionid` will be missing.
3. Pass the file with `--cookies`.

That file is a full account credential. `cookies.txt` and `cookies.json` are gitignored
here; treat it like a password and re-export when it expires.

Cookies alone are not enough for a plain HTTP client (which is why this is not a pure
`requests` script): TikTok's upload endpoints require
request signatures (`X-Bogus` / `_signature` / `msToken`) generated by obfuscated in-page
JavaScript. This tool therefore loads the cookies into a headless Chromium, which
restores the session and signs its own requests.

## Web UI

```bash
tthq serve --cookies cookies.txt
# http://127.0.0.1:8420
```

Drag in a clip, set the title and hashtags (live caption preview with a 2200-character
counter), pick the encode options, and watch progress stream in the log. "Dry run" is on
by default: it stages the post and fills the caption but never clicks Post, so you can
verify everything in a screenshot first.

The server binds to `127.0.0.1` on purpose — it reads a live session cookie and must not
be exposed to your network.

## CLI

```bash
# Inspect a clip and report what will hurt quality
tthq probe clip.mp4

# Encode only
tthq encode clip.mp4 -o clip-ready.mp4 --quality max --fit crop --denoise

# Encode and upload
tthq upload clip.mp4 --cookies cookies.txt \
  --title "1v5 clutch on Ascent" --hashtags "valorant, gaming, clutch"

# Stage the post without publishing, with a visible browser
tthq upload clip.mp4 --cookies cookies.txt --dry-run --headful
```

### Encode options

| Flag | Default | Notes |
| --- | --- | --- |
| `--resolution` | `1080` | `1080`/`1440`/`2160` vertical. 1080x1920 is TikTok's canvas; the taller options exist to A/B whether TikTok's own downscale looks better on your footage. |
| `--quality` | `max` | `safe` ≈10, `high` ≈15, `max` ≈20 Mbps at 1080x1920/30fps, scaled by pixels and frame rate. |
| `--fps` | match source | Capped at 60. Prefer 30 for detail, 60 for fast motion. |
| `--fit` | `pad` | `pad` letterboxes, `crop` fills 9:16, `stretch` distorts. |
| `--denoise` | off | Light `hqdn3d`. Helps grainy or dark gameplay survive the transcode. |
| `--two-pass` | off | Slower, marginally better bitrate distribution. |

## Caveats

- Browser automation depends on TikTok Studio's DOM. If selectors break, the error names
  the ones it tried and saves a screenshot next to the job artifacts.
- TikTok injects modals and tooltips mid-flow ("Turn on automatic content checks?",
  feature announcements) whose overlays swallow clicks. They are dismissed
  automatically, and because they are triggered by upload progress, every click is
  retried behind a fresh dismissal pass rather than assuming a clear page.
- Automated posting is against TikTok's terms of service in spirit if not always in
  letter; keep volume human-shaped and expect occasional captchas or verification prompts,
  which `--headful` lets you solve by hand.
